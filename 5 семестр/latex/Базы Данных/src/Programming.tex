\subsection{Задача} 

Реализовать представление на основе таблиц базы данных музея, а также составить простой и сложный запрос, используя данное представление. Простой запрос - это запрос непосредственно к представлению, а в сложном запросе обязано присутствовать соединение представления с другими таблицами базы данных (при помощи JOIN). \par


\subsection{Представление}

\textbf{Условие для формирования представления:} Для каждой записи о сотруднике (определяется полями id-сотрудника, именем и фамилией) найти число курируемых выставок и число уникальных типов среди этих выставок. \par

\vspace{8pt}

Текст представления представлен в Листинге~\ref{lst:view1}.

\vspace{8pt}

\lstinputlisting[language=SQL, caption={Представление employee\_curation\_stats}, label={lst:view1}, basicstyle=\ttfamily\footnotesize]{queries_view/view1.sql}

Реляционная формула представления:
\[
\begin{gathered}
R =
\gamma_{\substack{\text{employee\_id}, \text{first\_name}, \text{last\_name}; \\ \text{COUNT}(\text{distinct } \text{exhibition\_id}), \\ \text{COUNT}(\text{distinct } \text{exhibition\_type\_id})}}
\left(
\begin{gathered}
\text{employees}
\bowtie_{\text{employee\_id}} \\
\text{exhibition\_curators}
\bowtie_{\text{exhibition\_id}} \\
\text{exhibitions}
\end{gathered}
\right), \\
\text{где } \bowtie \text{ --- это natural join}
\end{gathered}
\]

\subsection{Простой запрос}

\textbf{Текст запроса:} Найти все записи о сотрудниках, которые курировали больше 3 выставок и при этом курировали выставки более чем 1 типа. \par
Запрос обращается к представлению \texttt{employee\_curation\_stats} как к обычной таблице, без соединения с другими таблицами базы данных. Текст запроса представлен в Листинге~\ref{lst:view2}. \par

\lstinputlisting[language=SQL, caption={Простой запрос к представлению}, label={lst:view2}, basicstyle=\ttfamily\footnotesize]{queries_view/view2.sql}

Реляционная формула запроса:
\[
\begin{gathered}
R =
\pi_{\substack{\text{first\_name}, \, \text{last\_name}, \\ \text{curated\_exhibitions\_count}, \\ \text{curated\_exhibition\_types\_count}}}
\left(
\sigma_{\substack{\text{cur\_exhibitions\_count} > 3 \ \land \\ \text{cur\_exhibition\_types\_count} > 1}}
\left(
\text{ECS}
\right)
\right), \\
\text{где ECS - это employee\_curation\_stats}
\end{gathered}
\]

\subsection{Задача}

Реализовать таблицу, содержание которой повторяет представление \\ \ViewName{}. Обеспечить её актуальность с помощью триггеров: при изменении данных в таблицах \texttt{employees}, \texttt{exhibitions}, \CuratorsTable{} содержимое созданной таблицы должно пересчитываться автоматически. \par

\vspace{8pt}

Должно быть реализовано 6 триггеров, покрывающих следующие изменения:
\vspace{-6pt}
\begin{enumerate}[noitemsep]
    \item добавление факта кураторства выставки;
    \item удаление факта кураторства выставки;
    \item изменение типа выставки;
    \item изменение данных сотрудника (имя, фамилия);
    \item удаление выставки;
    \item удаление сотрудника.
\end{enumerate}

\vspace{8pt}

Сформированы тестовые примеры, покрывающие все варианты изменения данных исходных таблиц. Результаты выполнения различных действий, влияющих на \TableName{} посредством триггеров, представлены в Таблице~\ref{tab:trigger-test-cases}.

{\Large \textbf{\section{Лабораторная работа №3 <<Права пользователей>>}}} \par
\noindent

\subsection{Задача} \noindent

Создать двух пользователей базы данных, обладающих различными правами доступа. 
Первый пользователь должен быть предназначен для просмотра сводной информации про кураторов выставок.
Второй пользователь должен быть предначен для манипулирования данными, связанными с кураторами выставок. \par

\vspace{-5pt}

\begin{enumerate}[noitemsep]
    \item Пользователь 1 (\texttt{guinea\_pig}) может только просматривать \\ \TableName{}. Ему доступна только операция \texttt{SELECT} из этой таблицы, ко всем остальным таблицам доступа нет.
    \item Пользователь 2 (\texttt{ex\_curator}) имеет полный доступ (\texttt{SELECT}, \texttt{INSERT}, \texttt{UPDATE}, \texttt{DELETE}) только к тем таблицам, изменения которых влияют на \\\TableName{}. К самой \TableName{} у него есть только право просмотра (\texttt{SELECT}), ко всем остальным таблицам доступа нет.
\end{enumerate}

\subsection{Обоснование распределения прав}

\noindent

\textbf{Пользователь 1 (\texttt{guinea\_pig})}. Данный пользователь создан для просмотра сводной информация о кураторах выставок (\TableName), он не должен видеть исходные таблицы (например, \texttt{employees} с телефонами сотрудников) и тем более менять их содержимое. Поэтому данному пользователю выдано только право \texttt{SELECT} на одну таблицу. \par

\vspace{8pt}

\textbf{Пользователь 2 (\texttt{ex\_curator}).} Данный пользователь создан для работы с данными, связанными с кураторами выставок: сотрудниками, выставками и фактами кураторства. Так как в таблице \TableName{} агрегируется информация по кураторству, пользователю было выдано право просмотра данной таблицы. Для вставки новых записей в таблицы \texttt{employees}, \texttt{exhibitions} и \\ \CuratorsTable{} ему также выданы права на последовательности (\texttt{SERIAL}) их первичных ключей. Права на запись в \TableName{} у него нет, так как если бы он мог писать в неё напрямую, то значения перестали бы соответствовать реальным данным. В реализованной БД актуальность данных в таблице \TableName \, поддерживается триггерами. \par

\vspace{8pt}

% \textbf{Триггерные функции.} По умолчанию функция триггера выполняется с правами того, кто изменил таблицу. Из-за этого любое изменение таблиц пользователем \texttt{ex\_curator} завершалось бы ошибкой \texttt{permission denied}, потому что триггер не смог бы записать результат в \TableName{}. Чтобы не выдавать пользователю права на запись в агрегат, все шесть триггерных функций выполняются с правами владельца (\texttt{SECURITY DEFINER}). \par

Последовательность действий и результат по каждой группе запросов: \par

\vspace{-6pt}
\begin{enumerate}[noitemsep]
    \item Запрос 1: чтение \TableName{} разрешено обоим пользователям. Для \texttt{guinea\_pig} это единственная разрешённая операция.
    \item Запросы 2--4: запись в \TableName{} (\texttt{INSERT}, \texttt{UPDATE}, \texttt{DELETE}) запрещена обоим пользователям. Данные в таблице после запросов не изменились.
    \item Запросы 5--7: работа с исходными таблицами. Для \texttt{guinea\_pig} все операции запрещены, а \texttt{ex\_curator} успешно выполняет чтение, вставку, изменение и удаление. 
    \item Запросы 8--9: обращения к посторонней таблице \texttt{passports} запрещены обоим пользователям как на чтение, так и на изменение.
\end{enumerate}
